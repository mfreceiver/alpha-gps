# 遥控拍摄：当前实现决定（0.5.0）

本文件记录 d8728cc 五路静态评审后确定的统一方向，供 0.5.0 及后续实现遵循。行为契约仍以 [research.md](research.md) 为准；视觉与交互冲突时，按 **v3 + 0.3.0 玻璃组件库 + 本文件 + 当前代码** 裁决。`remote-control-design.html`、PDF 与 `screens/` 保留为研究阶段的历史方案，不再把其中的小取景卡、80dp 胶囊或旧组件参数逐项照搬到实现。

## 1. Wi-Fi 取景（R2）

- 保留**全屏 Viewer**，不回退到研究稿中的页面内小取景卡。取景、返回、快门、重连和拍摄状态沿用现有 R2 状态机；本轮不新增参数面板或独立对焦。
- 取景页使用与照片预览一致的暗色 Viewer 主题、GV 控件、onPhoto 颜色角色和 `safeDrawing` 安全区。文件名/相机名与状态必须放在 GV 玻璃托底或暗化遮罩上，不得无底叠在亮画面上。
- 高频实时帧默认不作为每帧 Haze 模糊取样源；取景内的 Viewer 玻璃使用显式实色回退。照片预览继续使用自己的局部 backdrop。以后如需实时帧模糊，必须先通过真机性能验证，不能靠根背景的偶然取样行为实现。
- 等待、暂停和不支持等信息使用方形 `InfoTag(style = OnPhoto)`；重连、拍摄等操作使用胶囊。等待取景显示进度，快门不可用时在旁边给出原因。
- 拍摄状态使用固定占位槽，Idle、Shooting、Captured、Uncertain、Rejected 切换不得移动快门。横屏采用左右分区，控制区限宽并可在大字体下滚动。
- 本轮**不新增遥控 → 照片传输的直接切换入口**，避免在风格整改中引入新的会话切换语义；仍从设备页进入照片传输。研究稿中的该入口留待以后单独评审。

## 2. 蓝牙快门（R1）

- 保留首次进入确认、位置联动兼容提示、GPS 恢复基线和现有 BLE 状态机，不宣传“已拍摄/已保存”。
- 页面恢复 AlphaGPS 的卡片结构：相机名、连接状态、固定状态槽、拍摄区和底部全宽 Tonal“切换到 Wi-Fi 取景”。失败或失联使用带恢复动作的 `GlassWarningCard`，不能靠追加按钮让整页重新居中。
- 72dp 圆形双环 `GlassShutterButton` 是组件库已经收录的**明确快门例外**，不改成研究稿的 80dp 胶囊，也不要求它是 GlassIconButton 或 Haze 材质。其余文字、颜色、触控和无障碍规则不变。

## 3. 模式选择与连接

- 两种模式均显示图标、简短名称和说明；蓝牙使用 Secondary/Tonal，Wi-Fi 使用 Primary，动作按钮全宽。禁用原因紧邻对应卡片，并明确“仅进入本页不会自动连接”。
- 手动/回退连接在照片传输和遥控之间复用同一内容组件：560dp 限宽、G1 卡片分组、每屏至多一个 Primary、卡内按钮全宽、`GlassWarningCard`、进度和 `liveRegion`。
- 连接叠层保留自定义分段 `StepRing`，但总段数由调用方决定：照片传输 4 段，Wi-Fi 遥控 3 段。带“去授权/打开 Wi-Fi 设置”等动作时，点击卡片内容不得退出叠层。
- 只有真实照片或取景内容默认禁止作为背景取样源；普通模式选择、BLE 和连接页沿用默认玻璃取样。

## 4. 验证边界

- JVM/Compose 测试负责 AlphaType/颜色角色、对比度阈值、固定状态槽、弹层宿主与基本语义；样式守卫负责禁止硬编码字号/颜色，不能把“守卫通过”当作视觉验收。
- 真机仍需覆盖亮/暗主题、亮照片、360dp、横屏挖孔、200% 字体、TalkBack、Haze 性能，以及 research.md 中的相机型号、取景首帧、停帧重连和 GPS 并用矩阵。
- R3 参数面板与 R4 对焦仍是后续能力，不属于 0.5.0 的缺陷或交付范围。
